Reading a feed in Python

A feed is XML with a fixed shape, so the standard library is enough. The awkward part is that RSS and Atom use different element names and Atom puts everything in a namespace - the code below handles both.

import csv
import xml.etree.ElementTree as ET

ATOM = {"a": "http://www.w3.org/2005/Atom"}
RSS = {"c": "http://purl.org/rss/1.0/modules/content/"}


def parse_feed(path):
    root = ET.parse(path).getroot()

    # Atom: <feed><entry> ... </entry></feed>
    entries = root.findall("a:entry", ATOM)
    if entries:
        for entry in entries:
            link = entry.find("a:link", ATOM)
            yield {
                "title": entry.findtext("a:title", "", ATOM),
                "link": link.get("href", "") if link is not None else "",
                "published": entry.findtext("a:published", "", ATOM),
                "summary": entry.findtext("a:summary", "", ATOM),
            }
        return

    # RSS 2.0: <rss><channel><item> ... </item></channel></rss>
    for item in root.iter("item"):
        yield {
            "title": item.findtext("title", ""),
            "link": item.findtext("link", ""),
            "published": item.findtext("pubDate", ""),
            "summary": item.findtext("description", ""),
        }


with open("feed.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.DictWriter(f, fieldnames=["title", "link", "published", "summary"])
    writer.writeheader()
    writer.writerows(parse_feed("feed.xml"))

One script that reads both Atom and RSS 2.0

Atom puts every element in the http://www.w3.org/2005/Atom namespace, which is why the element names come through as a:entry in ElementTree. RSS 2.0 has no namespace at all, so it is just item.

Two details are easy to get wrong: the Atom link is an attribute (href), not text, and there is often more than one link element - a self link, an alternate link - so pick the one whose rel is alternate. The converter above picks the first link it finds.

One row per entry, in feed order. The URL lands in the link__@href column, because an Atom link carries its address in an attribute rather than in text - the converter keeps the attributes of leaf elements and prefixes them with @. The link column is therefore empty.

FAQ

Frequently asked questions

Feed formats, namespaces and the fields worth keeping.

How do I turn an RSS feed into a CSV?
Parse the XML, take the item or entry elements, and write one row per item. The converter above does it in the browser; the Python snippet reads the file directly. Either way the result is one row per feed entry.
What about Atom feeds?
Atom uses <feed><entry> instead of <channel><item>, and every element sits in the http://www.w3.org/2005/Atom namespace. The converter detects both, and the Python snippet shows how to read either one.
How do I handle namespaces?
Register the namespace prefix before parsing, or use a prefix map in the element lookup. ElementTree will otherwise report elements as ns0:entry with the namespace turned into a generated prefix - which still works, but is unreadable.
Can I convert a sitemap the same way?
Yes. A sitemap is a plain <urlset> of <url> elements, so the same converter flattens it into a list of pages with their locations and dates.
Which feed fields are worth keeping?
Title, link and published date cover most uses. Add the description if you want the summaries, and category or author if you want to group the items. The converter flattens whatever the feed carries, so you can see exactly what is there before you decide.
